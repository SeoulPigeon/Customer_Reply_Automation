# 한국갭이어 고객 문의·후속관리

직원이 Gmail·전화 문의를 접수하고 S0~S6 상태를 선택한 뒤 답변을 검토·발송하는 내부 웹 애플리케이션입니다. 고객이 답장하지 않으면 SQLite에 저장된 승인 문구로 후속 연락을 예약합니다. 답장이 오면 해당 상담의 예약을 취소하고, 연락 거부는 관련 고객 전체의 후속을 차단합니다.

기본값은 **모의 Gmail·모의 답변 생성**입니다. 실제 Gmail 발송은 관리자 검증과 활성화 전까지 차단됩니다. 포함된 35개 문구는 모두 **승인 대기**로 시작합니다. S6 후속 연락은 매번 직원 확인·승인이 필요합니다.

## 직원 직접 검수

몰타 가상 문의와 S4 시간 이동을 직접 시험하려면 [검수 실행 안내](docs/TEST_DRIVE.md)를 따라 `python -m app.demo`로 실행하세요. 첫 실행에서 본인이 로그인 계정을 만듭니다. 별도 검수 DB에서 S4 문구 5개만 승인하며 실제 Gmail·OpenAI·Sheets 연결은 차단합니다. Windows와 macOS/Linux 명령은 안내에 구분되어 있습니다.

문구의 기준 저장소와 시트 수정 반영 여부도 [검수 실행 안내](docs/TEST_DRIVE.md)에 설명되어 있습니다. 이후 연동 설정값·권한은 [연결 설정 안내](docs/CONNECTION_SETTINGS.md)를 참조하세요.

초안 자동 저장·동시 편집 충돌 감지, 같은 상태 저장 시 예약 유지, 최신 문의 우선 배치와 대시보드 카드 이동을 개선했습니다. 직원 화면은 필요한 입력과 다음 할 일을 먼저 표시하고 상세 정보는 접습니다. Gmail 연결은 관리자 OAuth 화면으로 진행합니다.

현재 우선 배포안은 [Render 웹 서비스 1개·영속 디스크 1GB](docs/RENDER_DEPLOYMENT.md)입니다. 비용 확인·사용자 승인·실제 서비스 생성·외부 API 인증은 대기 중이며 발급된 운영 HTTPS 주소는 없습니다. [최신 진행표와 사용자가 직접 할 작업](docs/LIVE_ROLLOUT.md)에서 비용·인증·실제 메일 확인 순서를 확인하세요. 기존 [Linux VPS 배포 구성](docs/DEPLOYMENT.md)은 대안으로 유지합니다.

## 로컬 실행

Python 3.12 이상을 사용합니다. 저장소 루트에서 실행합니다.

```bash
python -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.lock
python -m app.cli init --username admin
python -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

초기화 명령에서 관리자 비밀번호를 입력합니다. 고정된 기본 비밀번호는 없습니다. 비대화형 초기화는 비밀값으로 주입한 `APP_BOOTSTRAP_PASSWORD`를 사용합니다. 로그인 후 **모의 문의 등록 → 고객 상세 → S0~S6 선택 → 초안 생성 → 수정·승인 발송** 순서로 동작을 확인합니다.

일반 직원 계정은 다음 명령으로 생성합니다.

```bash
python -m app.cli create-user --username staff --role staff
```

환경 변수의 목록은 [.env.example](.env.example), 직원 사용법과 인증·배포·복구 절차는 [운영 설명서](docs/OPERATIONS.md)를 참조하세요. `.env.example`은 설정 예시이며 비밀값을 포함하지 않습니다. 환경 변수는 실행 프로세스에 주입해야 합니다.

## 구조

| 구성 | 역할 |
| --- | --- |
| FastAPI + HTML/CSS/JavaScript | 로그인, 상담·초안·전화·예약·문구·관리자 화면 |
| SQLite | 고객, 상담, 승인, 상담이력, 예약, 발송 기록의 기준 저장소 |
| Python 예약 실행기 | Gmail 확인, 예약 실행, 예외 처리 |
| Gmail 어댑터 | 수신·발신 조회, 스레드 답장, 발송 기록 대조 |
| OpenAI 어댑터 | 직원이 고른 상태와 확인된 정보로 편집 가능한 초안 작성 |
| Google Sheets 어댑터 | SQLite 운영 데이터를 보고용 시트로 단방향 내보내기 |
| `data/followup_templates.xlsx` | 사용자 제공 원본 35개 문구, 최초 초기화 데이터 |

예약 기준은 직원이 승인한 답변의 **실제 발송 시각**입니다. 자동 후속 발송은 기준 시각을 변경하지 않습니다. 기본 시간대는 `Asia/Seoul`이며, 영업시간 밖의 예약은 다음 허용 시간으로 미룹니다.

| 상태 | 누적 경과 일수 |
| --- | --- |
| S0·S1 | 3, 7, 14, 30, 60 |
| S2·S3 | 2, 5, 10, 21, 45 |
| S4·S5 | 1, 3, 7, 14, 30 |
| S6 | 1, 2, 5, 7, 14 — 직원 확인 후 발송 |

현재 배포·연동 상태와 운영 전 미해결 항목은 [최신 진행표](docs/LIVE_ROLLOUT.md), 이전 사용성 개선 결과는 [이전 개발 보고서](docs/IMPLEMENTATION_REPORT.md)에 정리했습니다.

## 검증

```bash
python -m pytest -q
```

테스트는 임시 SQLite와 모의 외부 서비스를 사용합니다. 실제 고객에게 발송하지 않습니다. A~I 업무 흐름, 미승인 문구 차단, 고객 답장 시 취소, 중복 실행, 영업시간, 버전 관리, 인증·권한과 외부 어댑터 요청을 검증합니다. 실제 계정의 Gmail·OpenAI·Sheets 연결 성공은 모의 테스트 결과와 별도로 확인해야 합니다.

## 운영 전 확인

실제 Gmail OAuth 권한, 회사 Google Sheets 접근 권한, 사용 가능한 OpenAI 모델, 발송 동의·적법한 연락 조건, HTTPS와 백업·보관 정책을 준비해야 합니다. 결제 시스템 연동은 없으므로 S6 진행 상태는 직원이 확인합니다.

Gmail 조회와 발송은 하나의 원격 트랜잭션으로 묶을 수 없습니다. 발송 직전 재조회와 로컬 중복 방지를 적용하지만, 마지막 Gmail 조회 이후 도착하는 메일까지 원자적으로 차단하는 보장은 제공하지 않습니다. 자세한 판단과 복구 원칙은 [설계 결정](docs/DECISIONS.md)에 기록했습니다.

S7, 출국·현지·종료 이후 관리, 문자·카카오톡, 채널톡, n8n, AI의 상태 자동 확정은 개발 범위에 포함하지 않습니다.
