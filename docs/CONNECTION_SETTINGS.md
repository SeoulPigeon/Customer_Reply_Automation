# 실제 Gmail·OpenAI 연결과 제한된 발송 확인

현재 상태는 **코드 구현·모의 API 검증 완료, 실제 인증·외부 API 검증 대기**입니다.
현재 우선 배포 대상은 Render입니다. 연결된 Render 계정은 없으며 Gmail 계정이나 OpenAI 키를 추측해 연결하지 않았습니다. 별도 도메인 없이 Render가 실제 발급한 기본 HTTPS 주소로 제한 시험을 준비합니다.
사용자가 지정한 확인용 수신 주소는 배포 후 관리자 화면에 등록합니다. 코드에 고정하지 않습니다.

`app.demo`는 계속 모의 실행 전용입니다. 실제 연동은 별도 운영 데이터 디렉터리와 `app.main`을
사용합니다. `.env`는 자동으로 읽지 않습니다. [Render 배포 안내](RENDER_DEPLOYMENT.md)에 따라 해당 서비스의 **Environment**에 비밀값을 등록합니다. Render에서는 `/var/data` 영속 디스크를 사용합니다. 대안인 VPS에서는 [별도 배포 안내](DEPLOYMENT.md)의 systemd 환경 파일을 사용합니다. 비밀값은 호스팅의 Secret 설정이나 서버 편집기에만 입력하며 채팅·소스·일반 로그·브라우저 저장소에 넣지 않습니다.

## 사용자가 준비할 항목

| 준비할 것 | 생성·선택하는 화면 | 안전하게 넣을 위치 | 입력 후 확인 | 성공 표시 |
| --- | --- | --- | --- | --- |
| Render 웹 서비스·영속 디스크 | Render → New → Blueprint → 기존 저장소·검수 브랜치 | `render.yaml`; 시작 시 실제 `RENDER_EXTERNAL_URL`을 `APP_BASE_URL`로 반영 | 비용 승인 후 생성, Live 상태와 HTTPS 외부 접속 확인 | 로그인 화면, 유효한 인증서 |
| Google OAuth 웹 클라이언트 | Google Cloud Console → 프로젝트 → Gmail API 사용 설정 → Google Auth Platform의 Branding/Audience/Data Access/Clients | Render 서비스 **Environment**의 `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET` | 재시작 후 관리자 → Gmail 연결 | Google 계정 선택 화면 |
| 연결할 Gmail 계정 승인 | 사이트의 Gmail 연결 → Google의 계정 선택·권한 승인 | 앱이 `/var/data/secrets/gmail-token.json`에 자동 저장 | 앱으로 돌아온 뒤 실제 요청으로 연결 검증 | 실제 계정 주소·Gmail 조회 성공 시각 |
| 수집 라벨과 시작 시점 | Gmail에서 전용 라벨 생성; 사이트 관리자 → Gmail 연결·수집 범위 | 관리자 화면의 라벨·시작 시점 | 범위와 건수 먼저 확인 → 확인한 범위 적용 → 문의 확인 | 마지막 수신 성공 시각, 범위에 해당하는 상담 |
| OpenAI 프로젝트 키·모델 ID | OpenAI Platform → 선택한 Project → API keys, 모델 접근 권한·Billing/Limits | Render 서비스 **Environment**의 `GAPYEAR_OPENAI_API_KEY`, `OPENAI_MODEL` | 재시작 후 실제 요청으로 연결 검증 | 실제 생성 성공, 모델·요청 ID·사용량 |
| 확인용 수신 주소 | 관리자 → 운영·발송 설정 | 확인용 실제 수신 주소 | 연결 검증 단계 저장 | 지정 수신자에만 제한된 발송 가능 |
| 선택적 보고용 Sheets | Google Cloud Sheets API, Google Sheets 문서 공유 | 서버의 `SHEETS_*` 비밀 설정·문서 ID | 연결 검증 → Sheets 보고 데이터 동기화 | 동기화 완료, 보고 시트 내용 |

Render용 웹 서비스 1개·영속 디스크 1GB 구성을 준비했습니다. 현재 공식 요금은 네트워크 접근 제한으로 확인 대기이며, 가입·비용 승인·실제 생성은 하지 않았습니다. 서버가 상시 실행되고 SQLite가 영속 디스크에 보존되는지 실제 배포에서 확인해야 합니다. 무료 임시 미리보기를 운영 배포로 대체하지 않습니다.

## Gmail OAuth 설정

| 설정 | 의미 |
| --- | --- |
| `APP_MAIL_MODE=live` | 실제 Gmail 어댑터. 발송 활성화와는 별도입니다. |
| `APP_BASE_URL` | 실제 배포된 HTTPS origin. 경로·쿼리를 붙이지 않습니다. |
| `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET` | Google OAuth **웹 애플리케이션** 클라이언트 설정. |
| `GOOGLE_TOKEN_FILE` | 앱이 발급·갱신한 토큰을 저장하는 보호된 파일 경로. 직접 토큰을 붙여넣지 않습니다. |
| `APP_SECRET_DIR` | 토큰 파일 경로를 생략했을 때 사용할 비밀 디렉터리. Render는 `/var/data/secrets`, 대안 VPS는 `/var/lib/gapyear-secrets`. |
| `GMAIL_ALIASES` | 선택사항. 실제 연결 계정의 회사 발신 별칭을 쉼표로 구분합니다. |

Google Auth Platform → Clients에서 승인된 리디렉션 URI에
**관리자 화면의 ‘인증 복귀 주소’와 정확히 같은 값**을 등록합니다. 코드가 만드는 주소는
`APP_BASE_URL` 뒤에 `/api/connections/gmail/callback`을 붙인 값입니다.
아직 Render 서비스를 생성하지 않아 완성된 URL은 없습니다. 별도 도메인 구매는 이 단계의 선행 조건이 아닙니다. 실제 HTTPS 주소가 확정되면
서버 설정·관리자 화면·Google 설정 세 곳의 값이 일치해야 합니다. Google의 장기 운영 앱 검증에서 홈페이지·개인정보처리방침 도메인 소유 확인을 요구하면 별도 도메인을 준비해야 할 수 있으며, 이 요건은 Render HTTPS 제공과 구분합니다.

요청 범위는 다음 두 가지뿐입니다.

```text
https://www.googleapis.com/auth/gmail.readonly
https://www.googleapis.com/auth/gmail.send
```

Google 로그인 비밀번호, 메일 삭제 권한, Drive 전체 권한은 요청하지 않습니다. OAuth state는
로그인한 관리자 세션에 묶인 일회용 값이며 PKCE를 적용합니다. 성공한 code 교환 후 실제
Gmail 프로필을 읽어 선택된 이메일 주소를 확인합니다. 갱신 토큰은 0600 비밀 파일에 저장합니다.
직원 사이트 로그인 권한과 Gmail 연결 권한은 별도입니다.

토큰 만료 시 갱신하고 권한 회수·인증 만료 시 재연결 필요 상태를 표시합니다. Gmail 비밀번호를
프로그램에 입력하지 않습니다. 기존 고객 DB와 다른 Gmail 계정으로 바꿔 대화를 섞는 것은
차단하므로 다른 계정의 운영은 별도 데이터 디렉터리를 준비해야 합니다.

**사이트의 외부 공개와 Google OAuth 앱의 게시·검증은 별개**입니다. External 앱이 Testing이면
등록된 테스트 사용자만 인증할 수 있고 Gmail 범위를 사용하는 갱신 토큰은 일반적으로 7일 제한을
받습니다. Google 콘솔의 현재 제한과 Workspace 조직 정책을 확인하세요. Production으로 게시해도
민감·제한 범위 검증이 자동 완료되지는 않습니다. `gmail.readonly`는 제한 범위로 분류되며,
사용 형태와 예외 적용에 따라 Google 검증·보안 평가 절차가 필요할 수 있습니다.
관련 기준: [OAuth 토큰 만료](https://developers.google.com/identity/protocols/oauth2#expiration),
[Gmail API 권한 범위](https://developers.google.com/workspace/gmail/api/auth/scopes).

## 개인 메일을 가져오지 않도록 수집 범위 확정

1. Gmail 설정 → 라벨에서 **한국갭이어/문의** 같은 전용 사용자 라벨을 만듭니다.
2. 업무 문의에만 라벨을 붙입니다. Gmail 검색 옵션에서 수신 주소·발신자 등 실제 업무 조건을
   정한 뒤 ‘필터 만들기 → 라벨 적용’으로 자동화할 수 있습니다. 모든 개인 메일에 적용하지 않습니다.
3. 관리자 화면에서 라벨 이름과 수집 시작 일시(서울)를 입력하고 **범위와 건수 먼저 확인**을 누릅니다.
4. 건수·시점을 검토하고 확인한 범위를 적용합니다. 과거 메일 전체를 자동 이관하지 않습니다.
5. 수신 동기화 후 최초 문의와 수신 시각을 확인합니다. 이미 등록한 상담 스레드의 답장과
   Gmail 화면에서 직접 보낸 회사 답장은 라벨이 없더라도 계속 추적합니다.

라벨은 **프로그램의 처리 범위**이지 Google 인증 권한 자체의 라벨 제한이 아닙니다.
관련 없는 스레드는 상담·OpenAI 입력으로 가져오지 않습니다. 자동 회신·반송은 일반 문의와
구분하며, 메시지 ID로 중복을 제거하고 계정과 스레드로 상담을 연결합니다. 고객 답장이나
Gmail에서 직접 보낸 답장은 해당 상담의 이전 예약을 취소합니다. 연락 거부는 관련 고객 전체의
자동 후속을 차단합니다. Gmail 조회가 실패하면 답장 없음으로 간주하지 않고 발송을 보류합니다.

현재는 라벨 목록과 등록 스레드를 반복 조회합니다. History API 증분 수집은 없고 한 조회의
상한은 10,000건입니다. 상한 초과 시 중단하므로 오래된 라벨 전체를 계속 쌓아두는 대규모 운영에는
증분 동기화 개선이 필요합니다. 최초 과거 범위는 관리자가 미리보기로 직접 확인해야 합니다.

## OpenAI 설정과 확인

`APP_AI_MODE=live`, `GAPYEAR_OPENAI_API_KEY`, `OPENAI_MODEL`을 설정합니다. 대체 키 이름
`OPENAI_API_KEY`도 지원하지만 전용 이름이 우선합니다. 모델을 코드가 임의 선택하지 않습니다.
실제 계정에서 **Chat Completions와 JSON 객체 응답 형식**을 지원하는 모델 ID를 확인해 설정합니다.
키에는 선택한 프로젝트의 API 사용 권한·결제·할당량이 있어야 합니다.

관리자 **실제 요청으로 연결 검증**은 모델 존재 조회만 하지 않고, 비개인정보 시험 입력으로 실제
생성 요청을 보냅니다. 이 소량 요청도 API 사용량에 포함됩니다. 실제 상담의 **답변 생성**에서는
해당 고객의 최신 문의·필요한 이력·직원 선택 상태·확인된 프로젝트 정보·참고사항만 전송합니다.
다른 고객이나 개인 메일함 전체는 보내지 않습니다.

응답에는 모델·생성 시각·요청 ID·토큰 사용량을 기록합니다. API 실패 시 화면에 오류를 표시하고
모의 답변을 실제 결과처럼 대신 보여주지 않습니다. GPT는 초안만 만들며 상태 확정·수신자 변경·
발송 승인·예약 취소 권한을 갖지 않습니다. 확인되지 않은 일정·비용·참가 가능 여부·환불 조건은
확정하지 않도록 지시하고, 직원 확인사항은 고객 발송 본문과 분리합니다.

관리자 화면에서 일일 요청 수·토큰 수·화면 알림 기준을 설정합니다. 신규 DB 기본값은
`OPENAI_DAILY_REQUEST_LIMIT=100`, `OPENAI_DAILY_TOKEN_LIMIT=250000`,
`OPENAI_USAGE_ALERT_PERCENT=80`, `OPENAI_MAX_OUTPUT_TOKENS=2048`입니다.
실패·결과 불명 요청은 예약한 예상량을 보수적으로 계산합니다. 서울 날짜 기준 제한이며,
**실제 청구액 한도는 OpenAI 프로젝트의 Billing/Limits에서도 설정**해야 합니다.
알림은 관리자 화면 표시이며 이메일·문자 알림은 구현하지 않았습니다.

## 제한된 실제 시험에서 운영 전환까지

이 절차는 아직 수행하지 않았습니다. 현재 연결된 Gmail 계정이나 실제 생성·발송 결과는 없습니다.

1. 새 운영 관리자 계정으로 로그인합니다. Gmail 연결·수집 범위 확정·OpenAI 실제 생성 검증을 합니다.
2. 운영 설정에서 확인용 실제 수신 주소를 지정하고 단계를 **지정 수신자 연결 검증**으로 둡니다.
   사용자가 지정한 주소는 `lim@weyear.co.kr`입니다. 이 주소는 연결할 Gmail 계정을 의미하지 않습니다.
3. 해당 확인용 계정에서 연결된 Gmail로 실제 문의를 보내고 지정 라벨을 붙입니다. 사이트에서 수신을
   확인한 뒤 상세의 **확인용 상담으로 지정**을 누릅니다. 일반 고객 상담과 분리됩니다.
4. 연락 조건을 확인하고 제한된 실제 발송을 활성화합니다. 직원 상태 저장 → 실제 OpenAI 답변 생성 →
   최종 수정 → 발신 계정·수신자·제목·본문 확인 → 승인·실제 발송을 수행합니다.
5. 예약 취소를 실제로 확인하려면 이미 승인된 해당 상태의 문구 하나로 **확인용 후속 예약 1건**을
   미래 시각에 만듭니다. 일반 고객의 시계나 기본 간격은 바꾸지 않습니다. 승인 문구가 하나도 없으면
   관리자가 시험에 사용할 한 문구의 저장본만 직접 검토·승인해야 합니다. 프로그램은 대신 승인하지 않습니다.
6. 예약 실행 전에 확인용 계정에서 실제 답장을 보내고 수신 동기화합니다. 예약이 취소되고 새 문의
   상태 재선택이 필요한지 확인합니다. 단순히 답장이 있었다는 사실과 실제 예약 취소 증거를 구분합니다.
7. 최신 문의를 읽고 같은 상태 또는 다른 상태를 저장한 뒤 새 GPT 초안을 승인·실제 발송합니다.
   현재 상태와 맞는 승인 문구로 확인용 예약 1건을 다시 지정하고 실제 시각에 자동 발송되는지 확인합니다.
   영업시간·필수 치환값·연락 조건을 유지하고, S6이면 최신 미완료 확인과 건별 승인이 필요합니다.
8. 관리자 화면의 실제 수신·GPT 생성·직원 발송·답장 및 취소·예약 발송 증거를 검토합니다.
   필요한 증거가 없으면 제한 운영 전환이 차단됩니다. 확인 후 **제한 운영 · 지정한 상담 최대 5건**을 선택하고 설정을 저장합니다. 관리자가 실제 상담 3~5건을 하나씩 등록하며 자동 후속은 각 상담에서 따로 허용합니다. 기존 상담 전체에 일괄 적용하지 않습니다.

확인용 상담은 운영 전환 뒤 일반 고객 대상으로 승격하지 않습니다. 모의 데이터도 실제 발송
대상으로 바꿀 수 없습니다. 오래된 운영 예약은 일괄 실행하지 않고 개별 직원 검토로 남깁니다.
최종 발송 승인은 초안 버전·문의 세대·상태·수신자·제목과 결합되며 다른 직원 수정이나 새 답장으로
변경되면 다시 확인해야 합니다. Gmail API 성공은 메일 수신·열람 보장이 아닙니다.

## Sheets와 현재 문구의 기준

고객·상담·초안·예약·발송 결과·문구 버전의 기준은 **SQLite**입니다. 원본 Excel은 처음 35개
문구를 넣는 자료이고 재시작 시 덮어쓰지 않습니다. 후속 문구 메뉴에서 수정하면 새 버전이 승인
대기가 되며 관리자가 개별 승인합니다. 이번 변경에서는 원문과 기존 승인 상태를 바꾸지 않습니다.

Sheets는 선택 사항이며 **SQLite → Sheets 단방향 보고 내보내기**입니다. 문구 가져오기·양방향
동기화는 미구현입니다. **Google Sheets에서 문구를 바꿔도 사이트와 발송 문구에는 반영되지 않습니다.**
Sheets 장애가 원본 상담이나 발송 기록을 삭제하지 않습니다.

사용하려면 Google Sheets API와 `https://www.googleapis.com/auth/spreadsheets` 권한, 문서 편집
권한을 준비합니다. `SHEETS_SPREADSHEET_ID` 및 별도 `SHEETS_TOKEN_FILE` 또는
`SHEETS_CLIENT_ID`, `SHEETS_CLIENT_SECRET`, `SHEETS_REFRESH_TOKEN` 묶음을 보호된 서버 설정에
등록합니다. Gmail 연결 버튼은 readonly/send만 요청하므로 이 버튼으로 Sheets 권한이 생기지 않습니다.
Sheets용 최초 동의 화면은 아직 없으며 별도 관리자 OAuth 절차가 필요합니다. 토큰을 채팅에 보내지 않습니다.

문서에 **고객관리** 시트를 만들고 보고 전용으로 사용합니다. 관리자의 동기화는
`'고객관리'!A1:Z5000`을 전체 교체합니다. 이 범위에 별도 문구나 수동 업무 자료를 함께 두지 않습니다.
메타데이터 조회와 실제 쓰기 성공을 구분하고 지정한 시험 문서에서 동기화를 확인합니다.
