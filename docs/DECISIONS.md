# 업무 규칙과 설계 결정

## 기준 데이터와 변경 권한

SQLite가 고객·상담·상태·문구 버전·예약·발송 결과의 유일한 기준 저장소입니다. Google Sheets는 조회·보고용 복사본입니다. 시트에서 수정한 값은 SQLite로 역수입하지 않습니다. 시트 연결 장애가 발생해도 SQLite의 고객과 예약은 유지되며, 연결 복구 후 같은 데이터를 다시 내보낼 수 있습니다.

첨부 원본은 `data/followup_templates.xlsx`에 보존했습니다. SHA-256은 `c9081e062ed031ed9683048253b46fc8fc80ea076cd5b35ed9d5aaf7202ca06a`입니다. `후속문구_S0-S6` 시트의 35개 ID·11개 열·본문을 초기 데이터로 사용합니다. 초기화는 기존 문구 변경 이력과 승인 상태를 덮어쓰는 수단으로 사용하지 않습니다.

S0~S6은 직원만 선택합니다. 기존 상태와 같은 상태를 다시 선택할 수 있고 순서와 무관하게 이동할 수 있습니다. AI가 상태를 저장하거나, 도구를 실행하거나, 고객에게 바로 발송하는 기능은 없습니다. 고객 메일은 초안 생성을 위한 데이터로 전달하며 프로그램 명령으로 실행하지 않습니다.

## 예약과 중복 방지

직원이 승인한 답변이 실제로 발송된 경우에만 무응답 관리 주기를 시작합니다. 예약은 발송 시각에 일수를 더해 누적 계산하고, 영업시간 밖이면 뒤로 미룹니다. 자동 후속 문구 발송은 관리 주기의 기준 시각을 변경하지 않습니다.

고객의 새 답장·Gmail 직접 답장·상태 변경·종료는 해당 계정과 스레드에 연결된 상담의 예약을 중단합니다. 연락 거부·이메일 허용 해제와 발송 결과 불명확은 관련 고객 전체에 적용합니다. 새 문의가 없고 같은 상태를 다시 저장하면 초안·예약·기준일은 유지합니다. 새 답장 이후에는 같은 상태를 다시 선택할 수 있고, 새 답변을 승인·발송한 뒤 새 주기를 만듭니다. 전화 상담 등록이나 초안 생성만으로 이메일 주기를 시작하지 않습니다.

SQLite 트랜잭션과 예약·발송의 고유 식별자로 같은 작업을 여러 실행기가 동시에 차지하지 못하게 합니다. 외부 전송 시도는 영속 기록을 남깁니다. 성공 응답을 저장하지 못한 중단·시간초과는 성공 또는 실패라고 단정하지 않으며, Gmail의 결정적 메시지 식별자로 대조합니다. 대조 결과가 없다는 사실만으로 발송되지 않았다고 단정하거나 자동 재발송하지 않습니다.

Gmail에는 메일 수신 확인과 메시지 전송을 원자적으로 묶는 API가 없습니다. 발송 직전 최신 메시지를 조회하고 로컬 상태를 재확인하더라도 **최종 원격 조회 이후 전송 사이에 도착하는 답장**을 완전히 배제할 수 없습니다. 테스트는 답장이 마지막 확인 시점까지 도착한 경우와 로컬 동시 실행을 검증합니다. 이 한계를 실제 Gmail에서 절대적인 “정확히 한 번” 전달 보장으로 표현하지 않습니다.

## 문구 승인과 개인정보

35개 문구는 최초에 승인 대기입니다. 관리자만 승인하거나 승인을 취소할 수 있습니다. 승인 주체·수정·발송 이력을 남기고 발송 전에 다시 검증합니다. 미승인 문구는 예약 목록에 나타날 수 있어도 발송할 수 없습니다.

운영 시 로그인 계정은 승인된 회사 직원에게만 발급합니다. HTTPS 로그인 화면은 외부에서 접근할 수 있지만 고객정보·발송 API는 인증 없이 공개하지 않습니다. 업무 담당자는 연락 수신 허용 여부와 근거를 확인합니다. 광고성 여부, 법정 고지·수신 거부 안내·보관 기간 등 법무·운영 기준의 적합성은 회사가 확정해야 하며, 프로그램의 체크 항목이 법적 검토를 대신하지 않습니다.

개인정보가 포함된 SQLite, 백업, OAuth 파일, 환경 변수 파일은 Git에 포함하지 않습니다. 운영 데이터와 모의 테스트 데이터는 서로 다른 저장 경로를 사용합니다. 삭제 이후 백업에 남는 개인정보의 보관 기간도 별도로 관리합니다.

## 현재 외부 연결 범위

Gmail API, OpenAI API, Google Sheets API 어댑터를 구성하되 인증정보 없이 실행 가능한 모의 모드를 기본으로 사용합니다. 로컬·HTTP 모의 테스트는 실제 계정의 권한, 할당량, 회사 OAuth 정책 또는 모델 접근 권한을 입증하지 않습니다.

신청·결제 시스템 자동 조회, 공휴일 API, 실시간 Gmail Pub/Sub, S7 이후 관리는 구현 범위 밖입니다. Gmail은 주기 조회 방식을 사용하므로 수신부터 화면 반영까지 조회 주기만큼 지연될 수 있습니다.
