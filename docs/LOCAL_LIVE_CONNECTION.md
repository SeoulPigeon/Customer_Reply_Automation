# 맥북의 기존 사이트에서 실제 Gmail·OpenAI 연결

현재 목표는 **사용자 맥북의 `http://127.0.0.1:8001`에서 실제 연결을 확인하는 것**입니다.
Render 가입·결제·배포와 회사 서버 이전은 이번 작업에서 진행하지 않습니다.
회사 서버 상시 운영을 완료한 상태도 아닙니다.

Codex가 수정하는 `/workspace/Customer_Reply_Automation`은 맥북과 다른 환경입니다.
코드를 내려받고 아래 설정을 맥북에서 적용해야 합니다. Codex 환경에 저장한 값이 맥북으로 전달되지 않습니다.
이 안내는 기존 FastAPI 사이트·화면·DB 구조·외부 어댑터를 사용합니다. 새 프로젝트가 아닙니다.

## 먼저 확인한 코드

| 항목 | 실제 코드·설정 | 확인 결과 |
|---|---|---|
| Gmail 연결 시작 | 관리자 설정의 **Gmail 연결 / 재연결** → `POST /api/connections/gmail/start` | 기존 구현 |
| Google 인증 복귀 | `GET /api/connections/gmail/callback` | 기존 구현, 로컬 HTTP 허용 |
| Google 클라이언트 | `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET` | 기존 설정 이름 |
| 실제 문의 수집 | `app.main` 안의 수신·예약 반복 작업; `POST /api/mail/poll`로 수동 수신도 가능 | 수신·예약 처리 후 30초 대기. 실시간 보장 아님 |
| 실제 발송 허용 | 관리자 운영 설정의 `live_enabled`, 실제 Gmail 조회 검증, `verification_recipient`, `operation_mode=verification` | 환경변수로 승인을 우회하지 않음 |
| OpenAI | `GAPYEAR_OPENAI_API_KEY`, `OPENAI_MODEL`; 기존 Chat Completions 호출 | 기존 구현, 실제 시험 요청 가능 |
| 실제/모의 구분 | `APP_MAIL_MODE`, `APP_AI_MODE`의 `live` / `mock` | `app.demo`는 항상 모의 전용 |
| 새 로컬 실행 경로 | `app.local_live`가 비밀 JSON을 읽고 기존 `app.main` 실행 | 이번에 추가한 실행 보조 모듈 |

실제 연결에 필요한 최소 보완만 했습니다. 비밀 파일 로딩·로컬 실행 명령을 추가하고,
로컬 실제 실행에도 재시작 후 경과 예약 보류를 적용했습니다. OpenAI 오류는 인증·모델/권한·
결제/사용량·요청 제한·네트워크 문제로 구분하며 최신 연결 확인 결과가 이전 오류에 가려지지 않게 했습니다.
로그인·직원/관리자 권한·직원 발송 승인·문구 승인·S6 조건은 유지합니다.

## 1. 맥북에서 최신 코드와 개인 계정 준비

기존 서버를 실행하던 터미널에서 **Ctrl+C**로 중지합니다. 다른 프로세스가 8001 포트를 쓰면
먼저 그 프로그램을 확인하고 종료합니다. 포트를 임의 변경하거나 서버를 두 개 실행하지 않습니다.

최신 코드는 GitHub의 `SeoulPigeon/Customer_Reply_Automation`, `review/staff-test-drive` 브랜치에 있습니다.
ZIP으로 받았다면 해당 브랜치에서 **Code → Download ZIP**으로 받아 새 폴더에 압축을 풉니다.
기존 폴더와 `var` 데이터는 삭제하거나 덮어쓰지 않습니다. 이전 가상 고객을 실제 대상으로 옮기지 않습니다.

맥북 터미널에서 **`README.md`, `requirements.lock`, `app` 폴더가 함께 있는 프로젝트 폴더**로 이동합니다.
경로를 모르면 터미널에 `cd `까지 입력하고 Finder에서 프로젝트 폴더를 끌어다 놓은 뒤 Enter를 누릅니다.
`~` 홈 폴더에서 바로 설치하면 `requirements.lock`을 찾지 못합니다.

```bash
python3.12 -m venv .venv
.venv/bin/python -m pip install -r requirements.lock
.venv/bin/python -m app.local_live init
```

프롬프트에서 새 개인 관리자 ID와 비밀번호를 직접 정합니다. 비밀번호는 입력 중 보이지 않습니다.
기존 공유 테스트 비밀번호는 사용할 수 없습니다. 기본 계정은 없으며 다시 초기화해도 기존 계정의
비밀번호나 이미 저장한 인증값을 덮어쓰지 않습니다. 새로 만든 ID로 로그인합니다.

명령이 출력하는 **비밀 설정 파일 경로**를 확인합니다. 프로젝트 기준 위치는 다음과 같습니다.

```text
var/local-live/secrets/settings.json
```

이 파일은 `var/` 아래라 Git에서 제외됩니다. 폴더 권한은 0700, 파일 권한은 0600입니다.
PyCharm에서 이 파일을 열어 입력하면 됩니다. 채팅·GitHub·브라우저 코드에 키를 붙여넣지 않습니다.
`.env` 파일은 자동으로 읽지 않습니다. 이 실행 명령은 위 JSON 파일을 읽습니다.

## 2. OpenAI부터 독립적으로 연결

| 항목 | 사용자가 할 일 |
|---|---|
| 무엇을 준비하는가 | OpenAI API 프로젝트의 키, 결제/사용량 설정, 접근 가능한 모델 ID. ChatGPT/Codex 구독 로그인과 별개 |
| 어느 화면에서 생성하는가 | [OpenAI Platform](https://platform.openai.com/) → 사용할 Project → API keys; Billing/Limits와 모델 접근 권한 확인 |
| 어디에 입력하는가 | 아래 `configure-openai`의 숨김 입력으로 `var/local-live/secrets/settings.json`에 자동 저장. PyCharm에서 직접 편집도 가능 |
| 어떤 명령·버튼을 실행하는가 | 아래 `start` 실행 → 사이트 관리자 설정 → **OpenAI · Sheets 연결 → 실제 요청으로 연결 검증** |
| 성공하면 무엇이 보이는가 | OpenAI 행의 `verified: true`, 실제 모델·요청 ID·생성 시각·사용량. Gmail 승인 대기와 별도 결과 |

초기 JSON은 다음 네 항목이며 빈 문자열 안에 본인의 값을 입력합니다. Google 항목은 준비 전까지 비워 둡니다.

```json
{
  "GOOGLE_CLIENT_ID": "",
  "GOOGLE_CLIENT_SECRET": "",
  "GAPYEAR_OPENAI_API_KEY": "",
  "OPENAI_MODEL": ""
}
```

파일을 직접 편집하지 않으려면 서버를 Ctrl+C로 종료한 뒤 프로젝트 폴더에서 다음을 실행합니다.

```bash
.venv/bin/python -m app.local_live configure-openai
```

API 키 입력 프롬프트에 새 키를 한 번 붙여넣고 Enter를 누릅니다. 입력한 키는 화면과 셸 명령 기록에
표시되지 않습니다. 이어서 모델 ID를 입력하면 기존 Google 설정을 보존한 채 비밀 파일에 저장합니다.
키를 명령어 자체에 붙여넣지 않습니다. **채팅이나 공개 파일에 노출된 키는 OpenAI API keys에서 폐기하고
새로 발급한 키를 이 프롬프트에만 입력합니다.** 이 명령은 저장만 하며 실제 연결 성공은 아래 버튼으로 확인합니다.

모델은 본인 프로젝트에서 실제 사용할 수 있으며 **Chat Completions와 JSON 객체 응답**을 지원하는 ID를 넣습니다.
OpenAI Platform의 해당 프로젝트 Playground/모델 선택란에서 확인합니다. 확인하지 않은 모델을 기본값으로
정하지 않습니다. API 키는 해당 프로젝트의 생성 요청 권한이 필요합니다.
연결 검증 버튼도 고객정보 없는 짧은 **실제 API 요청**을 보내므로 API 사용량에 포함됩니다.
Google 항목이 비어 있어 Gmail 확인이 실패해도 OpenAI 검증은 이어서 수행합니다.
Sheets 미연결은 이 흐름을 막지 않으며 Sheets 설정이나 동기화 버튼은 이번에 사용하지 않습니다.

```bash
.venv/bin/python -m app.local_live start
```

같은 맥북 브라우저에서 **http://127.0.0.1:8001**을 열고 방금 만든 개인 계정으로 로그인합니다.
이 주소는 맥북에서 위 명령을 실행했을 때 열리는 주소이며 Codex 공개 미리보기가 아닙니다.
`localhost`로 바꾸지 않습니다. `app.demo`를 실행하면 다시 모의 모드가 되므로 사용하지 않습니다.

설정 파일을 수정한 뒤에는 실행 터미널에서 **Ctrl+C**, 이어서 같은 `start` 명령으로 재시작합니다.
설정 유무만 확인하려면 다른 터미널을 같은 프로젝트 폴더에서 열어 다음을 실행합니다.

```bash
.venv/bin/python -m app.local_live status
```

이 명령은 키·토큰의 값을 출력하지 않습니다. `configured`는 값이 입력되었다는 뜻이고,
`observations`의 성공 시각은 실제 요청 기록입니다. 둘을 구분합니다.

## 3. Google 설정과 정확한 반환 주소

Google에 등록할 **Authorized redirect URI**는 다음 한 주소입니다.

```text
http://127.0.0.1:8001/api/connections/gmail/callback
```

현재 사용자 사이트 주소와 기존 코드의 콜백 경로를 조합한 실제 로컬 설정입니다.
프로그램도 정확히 같은 주소를 사용하며 관리자 화면의 **인증 복귀 주소**에서 확인할 수 있습니다.
사이트를 계속 같은 브라우저·`127.0.0.1:8001`로 열고 서버 터미널을 켜 둔 상태에서 인증합니다.

| 항목 | 사용자가 할 일 |
|---|---|
| 무엇을 준비하는가 | 본인이 관리할 Google Cloud 프로젝트와 실제 연결할 Gmail 계정 |
| 어느 화면에서 생성·승인하는가 | [Google Cloud Console](https://console.cloud.google.com/)에서 아래 순서 진행 |
| 어디에 입력하는가 | `settings.json`의 `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET`; Google Clients의 Authorized redirect URIs에는 위 주소 |
| 어떤 명령·버튼을 실행하는가 | `start` 재시작 → 사이트 관리자 설정 → **Gmail 연결 / 재연결** → Google에서 본인 계정 선택·권한 승인 |
| 성공하면 무엇이 보이는가 | 관리자 화면의 Google에서 확인한 실제 이메일 주소와 **현재 연결 조회 성공**, 최근 조회 검증 시각 |

Google Console 순서:

1. 상단 프로젝트 선택 메뉴에서 기존 업무용 프로젝트를 선택하거나 직접 새 프로젝트를 만듭니다.
2. **APIs & Services → Library → Gmail API → Enable**을 누릅니다.
3. **Google Auth Platform → Branding**에서 앱 이름·사용자 지원 이메일·개발자 연락처를 본인 정보로 설정합니다.
4. **Audience**에서 개인 Gmail 또는 조직 외 계정을 연결한다면 **External**을 선택합니다.
   **Testing**으로 확인할 때 **Test users**에 실제 연결할 계정을 추가합니다.
   Workspace **Internal**은 해당 조직과 정책이 확인된 경우에만 선택합니다.
5. **Data Access**에서 다음 두 범위를 등록합니다.
   - `https://www.googleapis.com/auth/gmail.readonly`: 문의 원문·최신 답장·전송 기록 조회
   - `https://www.googleapis.com/auth/gmail.send`: 직원 승인 답장과 조건을 통과한 후속 발송
6. **Clients → Create client → Web application**을 선택합니다. Desktop app 클라이언트가 아닙니다.
   **Authorized redirect URIs**에 위의 정확한 로컬 주소를 추가합니다.
   서버에서 인증을 처리하므로 브라우저 JavaScript에 클라이언트 비밀값을 넣지 않습니다.
7. 클라이언트 ID·비밀값을 맥북의 JSON 설정에 직접 입력·저장하고 프로그램을 재시작합니다.
8. 사이트에서 Gmail 연결 버튼을 누르고 Google 화면에서 실제 발신·수신 계정을 직접 선택합니다.
   동의한 두 범위가 승인되어야 합니다. Gmail 비밀번호를 앱이나 채팅에 입력하지 않습니다.

`lim@weyear.co.kr`는 **확인용 수신자**입니다. 연결할 Gmail 계정으로 지정하지 않습니다.
앱은 토큰 교환 후 Gmail 프로필을 조회해 실제 연결 주소를 확인합니다.
갱신 토큰은 `var/local-live/secrets/gmail-token.json`에 0600 권한으로 저장하며 브라우저에 저장하지 않습니다.
브라우저를 닫아도 프로그램이 실행 중이면 토큰 갱신·수집 작업이 계속됩니다.

External/Testing은 등록된 테스트 사용자 제한이 있고 Gmail 범위의 갱신 토큰은 일반적으로 7일 제한입니다.
재인증이 필요하면 사이트에서 재연결합니다. 장기 운영 시 게시·민감/제한 범위 검증 요건은 별도 확인해야 하며,
Production으로 게시했다고 Google 검증까지 완료되는 것은 아닙니다. 조직 정책으로 차단되면
Workspace/Google Cloud 관리자가 해당 OAuth 클라이언트·범위 사용을 허용해야 합니다. 정책을 우회하지 않습니다.

## 4. 수집 범위를 확정하고 실제 문의 보내기

1. 연결한 Gmail에서 **한국갭이어/문의** 같은 업무 전용 라벨을 만듭니다.
2. 사이트 관리자 **Gmail 연결 · 수집 범위**에서 그 라벨 이름과 새 문의 수집 시작 시점(서울)을 입력합니다.
3. **범위와 건수 먼저 확인 → 확인한 범위 적용**으로 대상·시점을 확정합니다.
4. 확인용 계정 `lim@weyear.co.kr`에서 **관리자 화면에 표시된 실제 연결 Gmail 주소**로 다음 문의를 보냅니다.
   “몰타 어학연수를 1월에 3주 정도 가려고 합니다. 참가 가능한가요? 비용도 궁금합니다.”
5. 해당 메일에 지정한 업무 라벨을 붙이고 수신 작업을 기다리거나 사이트의 수신 동기화를 실행합니다.
6. 상담의 원문·발신자·제목·수신 시각을 확인합니다. 관리자 화면의 **최근 메일 등록 지연**과
   실제 Gmail 수신/사이트 등록 시각을 기록합니다. 측정 전에는 수신 속도를 확정하지 않습니다.

개인 메일 전체와 과거 메일 전체를 자동 수집하지 않습니다. 이미 등록한 상담 스레드의 새 답장은
최초 라벨이 없어도 추적합니다. 회사 발신·고객 발신·자동 회신·반송을 구분하고 메시지 ID 중복을 차단합니다.
Google 권한 자체는 라벨 단위가 아니며 앱의 수집 규칙이 범위를 제한합니다.
조회 오류가 나면 최신 답장이 없다고 판단하지 않고 후속 발송을 보류합니다.

## 5. 실제 S4 초안 → 승인 발송 → 답장·예약 확인

관리자 운영 설정에서 확인용 실제 수신 주소를 `lim@weyear.co.kr`로 지정하고 단계를
**지정 수신자 연결 검증**으로 유지합니다. 수신된 해당 상담을 **확인용 상담으로 지정**합니다.
다른 고객이나 예전 모의 상담을 확인용으로 대신 사용하지 않습니다.

1. 직원이 최신 문의를 읽고 **S4 → 상태 저장 → 답변 생성**을 누릅니다.
2. 실제 OpenAI 모델·생성 시각·요청 기록과 초안을 확인합니다. 모의 응답으로 대체하지 않습니다.
   직원은 질문에 답하는지, 확인되지 않은 참가 가능 여부·비용을 만들지 않는지, 필요한 질문만 하는지,
   직원 확인사항이 고객 발송 본문과 분리되는지 확인합니다. 실제 모델 출력 전에는 품질 검수 완료가 아닙니다.
3. 연락 허용 근거와 수신자를 확인하고 관리자에서 실제 발송을 활성화합니다.
   직원이 본문을 수정한 뒤 수신자·제목·최종 본문을 확인하고 승인·발송합니다.
4. 사이트의 Gmail 전송 수락·메일 ID, 연결 계정 Gmail의 **보낸편지함**, 확인용 수신자의 **받은편지함**을
   각각 확인합니다. 전송 수락을 수신 또는 열람으로 간주하지 않습니다. CC·BCC 발송은 만들지 않습니다.
5. 예약 취소 확인을 위해 관리자가 사용할 **S4 문구 한 건만 직접 검토·승인**하고,
   해당 상담에 기존 기능의 **확인용 후속 예약 1건**을 미래 시각으로 만듭니다.
   확인 단계는 일반 고객의 5개 자동 예약을 만들지 않으므로 취소할 시험 예약이 먼저 필요합니다.
6. 시험 예약 실행 전에 `lim@weyear.co.kr`에서 실제 답장을 보냅니다. 사이트에 답장이 들어오고
   남은 예약이 취소됐는지 ID와 상태로 확인합니다. 직원 상태 재선택 대기로 바뀌어야 합니다.
7. 최신 답장을 읽고 같은 S4 또는 적절한 상태를 다시 선택하여 새 실제 초안·직원 승인 답장을 작성합니다.
   새 답장이 없는 상황에서 같은 상태를 저장하는 것만으로 기존 예약을 취소하지 않습니다.
8. 승인된 같은 문구로 확인용 짧은 예약 1건을 다시 만들어 실제 후속 발송을 확인합니다.
   전체 자동 후속 중지가 켜져 있다면 관리자가 시험 범위와 문구를 확인한 후 해제해야 합니다.
   영업시간·연락 조건·필수 치환값은 그대로 적용되므로 표시된 실행 예정 시각을 확인합니다.

정상 일정 전체를 앞당기거나 문구 전체를 승인하지 않습니다. S6은 신청·결제 확인과 건별 직원 승인을 유지합니다.
발송 결과가 불명확하면 새 메일로 재시도하지 않고 전송 기록을 대조합니다.
Gmail의 최종 답장 조회와 실제 발송을 하나의 원격 트랜잭션으로 묶을 수 없다는 기존 제한은 남습니다.

## 실행·저장·오류 확인

| 항목 | 실제 위치·동작 |
|---|---|
| 웹 주소 | `http://127.0.0.1:8001`, 맥북 내부에서만 수신 |
| 상담·초안·문구·예약·계정 | `var/local-live/data/app.sqlite3` |
| OAuth 수집 범위·AI 사용량 | 같은 디렉터리의 별도 SQLite 파일 |
| 비밀 설정·OAuth 토큰 | `var/local-live/secrets/` |
| 시작 전 DB 백업 | `var/local-live/backups/`, 기존 DB 구조 변경 전에 생성 |
| 수신·예약 프로세스 | `app.local_live start`로 시작한 단일 `app.main` 프로세스 |
| 실행·성공 상태 | `app.local_live status`, 사이트 관리자 실행 상태의 최근 수신·예약 성공 시각 |
| 중지·재시작 | 실행 터미널에서 Ctrl+C → 동일한 `start` 명령 |

실행 보조 모듈이 `APP_MAIL_MODE=live`, `APP_AI_MODE=live`, `APP_ENV=development`,
`APP_BASE_URL=http://127.0.0.1:8001`, `ENABLE_SCHEDULER=true`, `COOKIE_SECURE=false`와 개인 계정 검사
`APP_REQUIRE_PRODUCTION_ACCOUNTS=true`를 설정합니다. 로컬 HTTP이므로 Secure 쿠키는 쓰지 않지만
HttpOnly·SameSite·CSRF·Origin·Host·권한 검사는 유지하며 외부 인터페이스로 공개하지 않습니다.
토큰 경로와 데이터 경로도 이 모듈이 고정하므로 사용자가 별도 환경변수를 입력할 필요가 없습니다.

**맥북을 끄거나 잠자기 상태로 두거나 프로그램을 종료하면 수집·예약 작업도 멈춥니다.**
브라우저를 닫는 것만으로 서버가 종료되지는 않습니다. 재시작 중 경과한 예약은 개별 검토로 보류합니다.

OpenAI 오류는 화면에 원인과 다음 조치를 표시합니다. 키 오류는 파일의 키/프로젝트를 확인하고,
모델 오류는 모델 ID와 프로젝트 접근 권한, 결제 오류는 API Billing/Limits, 요청 제한은 대기 후 수동 재시도,
통신 오류는 맥북 인터넷·회사 프록시 정책을 확인합니다. 원본 공급자 오류 본문·키·고객 원문은 일반 로그에 출력하지 않습니다.

Google `redirect_uri_mismatch`는 위 주소·포트·경로와 클라이언트 종류를 확인합니다.
`access_denied`·`org_internal`·관리자 차단은 테스트 사용자, Audience, Workspace 정책을 해당 관리자와 확인합니다.
콜백에서 로그인 오류가 나면 같은 브라우저·같은 `127.0.0.1:8001`에서 다시 로그인한 뒤 연결을 시작합니다.

문구의 기준은 SQLite입니다. Sheets 미연결이어도 실제 Gmail·OpenAI 흐름은 동작합니다.
Sheets 문구 가져오기는 미구현이며 Google Sheets에서 편집한 문구는 사이트에 반영되지 않습니다.

## 현재 실제 결과

Codex 환경에는 인증값이 없고 사용자 맥북을 직접 제어할 수 없습니다. 로컬 코드 검증을 맥북 실제 연결 성공으로 보고하지 않습니다.

격리 데이터로 자동 검사 190개와 기존 직원 브라우저 흐름을 확인했습니다. 실제 실행기의 기동·재시작도
임시 루프백 포트에서 확인했으며, 개인 로그인·정확한 인증 반환 주소·빈 인증 설정의 오류 표시·발송 비활성을
검증했습니다. 이 검사는 Google/OpenAI의 실제 외부 호출을 수행한 결과가 아닙니다.

| 항목 | 실제 결과 | 남은 사용자 작업 |
|---|---|---|
| 실제 연결된 Gmail 계정 | 사용자 Google 승인 대기 · 연결 계정 미확인 | Google 클라이언트 설정 후 본인 계정 선택·승인 |
| 실제 문의 수신 | 실제 외부 검증 전 | 라벨·시작 시점 확정 후 확인용 실제 문의 발송 |

키·토큰은 전달하지 않습니다. 도움을 요청할 때는 설정 여부, 오류 코드·안전한 안내 문구,
실제 연결 계정 확인 여부와 발송 도착 여부만 알려주면 됩니다.
