# 직원 사용법과 운영 기준

배포 설치·HTTPS·백업·복원 명령은 [배포 안내](DEPLOYMENT.md), Google/OpenAI 인증과 실제 시험은
[연결 설정](CONNECTION_SETTINGS.md), 구현 여부와 검증 결과는 [개발 보고서](IMPLEMENTATION_REPORT.md)에 있습니다.
아직 실제 호스팅·외부 API 연결은 완료되지 않았습니다. 로컬 모의 사용은 [직접 검수](TEST_DRIVE.md)를 따릅니다.

## 직원의 상담 순서

1. 대시보드에서 신규 문의·상태 선택 대기·답변 검토 대기 등의 카드를 눌러 해당 고객 목록을 엽니다.
   카드와 목록은 같은 조건을 사용하며 숫자는 해당 상담 건수입니다.
2. 고객 상세 맨 위의 **최신 고객 문의**에서 발신자·제목·수신 시각·원문을 읽습니다.
3. S0~S6을 직접 선택하고 **상태 저장**을 누릅니다. 새 답장이 없고 같은 상태이면 예약·기준일은 그대로입니다.
   다른 상태로 바꾸면 영향을 받는 예약과 사유를 확인하고 저장합니다.
4. **답변 생성**으로 OpenAI 초안을 만듭니다. 모의 실행에서는 실제 GPT 생성이 아니라는 표시를 확인합니다.
   확인되지 않은 일정·비용·참가 가능 여부는 직원 확인사항을 읽고 확인합니다.
5. 초안을 편집하면 서버에 자동 저장됩니다. 저장 중·저장 완료·저장 실패 표시를 확인합니다.
   **상담 정보 저장**은 편집 중인 답변을 지우지 않습니다. 저장 실패 시 화면을 닫지 말고 재시도하거나
   내용을 보관합니다. 미저장 상태의 이동·새로고침은 경고하며, 저장 완료분은 재접속해도 복원합니다.
6. 다른 직원·창과 충돌하면 자동으로 덮어쓰지 않습니다. **충돌 내용 비교**에서 서버 최신본과 내 작성본을
   비교하고 합친 결과를 직접 확인해 저장합니다. 답변 재생성도 확인을 받고 기존 초안을 보존합니다.
7. **검토 후 발송**에서 발신 계정·수신자·제목·최종 본문을 확인하고 체크한 뒤 승인합니다.
   승인 화면 이후의 초안 변경·고객 새 답장·수신자 변경은 기존 승인으로 발송되지 않습니다.
8. **다음 후속 연락**에서 문구·예정일·처리 상태·보류 사유를 확인합니다. 전체 상담이력은 그 아래에 있습니다.

고객의 새 답장이 오면 해당 상담의 남은 예약이 취소되고 직원 상태 재선택을 기다립니다. 이전과
같은 상태를 다시 선택할 수 있습니다. 이전 초안은 보존되지만 새 문의의 답변으로 그대로 발송하지 않습니다.
전화번호만 있는 고객은 이메일 발송을 할 수 없으며 전화 상담 기록·다음 통화 업무로 관리합니다.

## 회사가 답해야 하는 상담

회사에서 운영정보를 확인하기로 한 경우 **회사가 운영정보를 확인해 답해야 합니다**를 선택합니다.
이 경우 고객 무응답 후속을 시작하지 않고 직원 확인 업무로 둡니다. 확인이 끝난 뒤 실제로 안내할
답변을 작성하고 직원 승인을 받아 발송해야 새 후속 주기를 만들 수 있습니다.

## 예약·취소·일시중지

기준은 직원 승인 상담 답변의 **정상 발송 시각**입니다. 상태 저장·초안 생성·자동 후속은 기준일을 바꾸지 않습니다.

| 상태 | 기준 발송일부터 누적 일수 |
| --- | --- |
| S0·S1 | 3·7·14·30·60 |
| S2·S3 | 2·5·10·21·45 |
| S4·S5 | 1·3·7·14·30 |
| S6 | 1·2·5·7·14, 건별 직원 확인·승인 |

서울 시간 영업 요일·시간 밖이면 다음 허용 시간으로 연기하고 원래 예정일은 보존합니다.
미승인 문구, 누락된 치환값, 연락 조건 미확인, 수신 동기화 장애는 보류합니다. S6은 최근 24시간
이내 미완료 확인과 해당 문구의 직원 승인이 필요합니다. 신청·결제 완료·중단 확인 시 관련 후속을 종료합니다.

- **후속 일시중지**는 해당 상담의 예약 기록을 보존한 채 실행을 보류합니다.
- **후속 재개**는 예약 영향과 사유를 보여줍니다. 경과한 실제 운영 예약은 개별 검토 대상으로 남깁니다.
- **전체 자동 후속 중지**는 관리자가 새 자동 후속을 멈춥니다. 고객·초안·예약을 삭제하지 않습니다.
- 연락 거부·이메일 허용 해제는 관련 고객 전체의 자동 후속을 차단합니다.
- Gmail 화면에서 직원이 직접 보낸 답장도 추적하여 해당 상담의 이전 예약을 취소하고 직원 확인으로 전환합니다.
- 모의 데이터는 운영 활성화만으로 실제 발송 대상이 되지 않습니다. 확인용 상담도 일반 운영으로 승격하지 않습니다.

중복 클릭·재시작에 대비한 고유 발송 기록과 SQLite 트랜잭션을 사용합니다. 발송 결과가 불명확하면
자동 재발송하지 않고 해당 고객의 추가 발송을 막습니다. Gmail 전송 기록 대조 후 처리합니다.
Gmail 조회와 전송은 원격에서 원자적으로 묶이지 않으므로 마지막 조회 이후의 답장 도착까지
절대적으로 차단한다고 주장하지 않습니다. API 성공은 상대방 수신·열람 보장이 아닙니다.

## 문구와 Sheets

기준 저장소는 SQLite `template_versions`입니다. 처음 생성할 때 원본 Excel의 35개 문구를
승인 대기로 넣습니다. 기존 문구와 승인 상태는 이번 개선으로 바꾸지 않습니다.
후속 문구 메뉴에서 수정하면 새 버전이 승인 대기가 되고 관리자만 개별 승인할 수 있습니다.
기존 예약의 버전을 새 문구로 몰래 교체하지 않습니다. 이전 버전이 승인 취소되면 발송을 보류합니다.

Sheets는 SQLite → Sheets의 관리자 수동 보고 내보내기입니다. **Sheets 문구 동기화는 미구현**이며
시트에서 문구를 바꿔도 사이트에 반영되지 않습니다. Sheets 장애가 SQLite 상담이나 발송 기록을 삭제하지 않습니다.

## 운영 화면과 복구

관리자 화면은 실제 수신·OpenAI 생성·직원 승인 발송·자동 후속 상태를 구분하고, 수신·예약의
마지막 정상 시각과 오류, 재연결 필요 여부, 제한된 실제 검증 증거를 보여줍니다.
OpenAI 일일 사용량 제한과 알림 기준도 설정할 수 있습니다. 알림은 화면 표시만 제공하며 별도
메일·문자 장애 알림이나 외부 가동 감시는 아직 없습니다.

Gmail 인증 문제가 있으면 재연결하고 수집 범위·실제 조회 성공을 확인합니다. OpenAI 실패는
실제 오류로 표시하며 모의 초안으로 대체하지 않습니다. 긴급 중지는 운영 서버에서
`sudo systemctl stop gapyear`로 수행합니다. 데이터·예약은 영속 디스크에 유지됩니다.
백업·복원은 [배포 안내](DEPLOYMENT.md)의 명령으로 수행하며 복원 후에는 자동 발송이 중지됩니다.

## 검증 명령

```bash
.venv/bin/python -m pytest -q
```

실제 브라우저 회귀 검사는 Node.js, Playwright, Chromium이 있는 개발 환경에서 실행합니다.
`PLAYWRIGHT_MODULE`은 설치된 Playwright 모듈 경로, `CHROMIUM_PATH`는 브라우저 실행 파일 경로로
지정할 수 있습니다. 운영 DB가 아닌 임시 모의 DB를 자동 생성합니다.

```bash
.venv/bin/python scripts/check_staff_ui.py --artifacts /tmp/gapyear-ui-check
```

자동 테스트와 이 브라우저 검사는 실제 Gmail·OpenAI API 성공이나 외부 HTTPS 배포 검증을 대신하지 않습니다.
