# 직원 입장에서 직접 검수하기

이 안내는 실제 고객에게 발송하지 않는 별도 검수 환경을 실행합니다. `python -m app.demo`는 Gmail·답변 생성을 모두 모의 방식으로 고정하며 Google Sheets 외부 동기화도 차단합니다. 실제 연동용 환경변수가 컴퓨터에 있어도 이 실행 경로에서는 사용하지 않습니다.

검수 데이터는 `var/demo/app.sqlite3`에 저장합니다. 일반 실행의 `var/app.sqlite3`와 구분하며, 기존 운영 데이터와 문구 승인 상태를 변경하지 않습니다. 화면의 초안은 **모의 응답이며 실제 GPT가 생성한 답변이 아닙니다.**

## 접속 방법

현재 클라우드 세션에는 사용자에게 전달할 공개 미리보기 주소를 발급하는 도구가 없습니다. 아래 주소는 클라우드 미리보기가 아니라 **아래 명령으로 서버를 실행한 본인 컴퓨터의 주소**입니다. 명령 실행 전에는 해당 사이트가 열리지 않습니다.

GitHub의 검수 브랜치에서 **Code → Download ZIP**으로 내려받고 새 폴더에 압축을 풉니다. GitHub가 만든 ZIP과 압축 해제 폴더 이름에는 브랜치명이 포함될 수 있습니다. **`README.md`, `requirements.lock`, `app` 폴더가 함께 보이는 프로젝트 폴더에서 터미널을 연 뒤** 아래 명령을 실행하세요. Python 3.12가 필요합니다. GitHub 로그인이 필요한 저장소라면 해당 저장소에 접근할 수 있는 계정으로 먼저 로그인합니다.

### Windows PowerShell

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.lock
.\.venv\Scripts\python.exe -m app.demo
```

가상환경 활성화 스크립트를 실행하지 않으므로 PowerShell 실행 정책 변경이 필요하지 않습니다. `py`를 찾을 수 없으면 Python 3.12 설치 및 Python Launcher 설치 여부를 확인합니다.

### macOS·Linux 터미널

```bash
python3.12 -m venv .venv
.venv/bin/python -m pip install -r requirements.lock
.venv/bin/python -m app.demo
```

최초 실행 때 로그인에 사용할 아이디와 비밀번호를 지정합니다. 안내된 기본 아이디를 선택하더라도 계정은 그때 실제로 생성됩니다. 미리 만들어진 공용 계정이나 기본 비밀번호는 없습니다. 비밀번호는 12자 이상이며 입력 중 화면에 보이지 않습니다. 생성 완료 메시지를 확인한 뒤 본인이 지정한 계정으로 로그인합니다. 다시 실행하면 기존 계정을 유지하며 비밀번호를 덮어쓰지 않습니다.

서버 시작 메시지가 나오면 **같은 컴퓨터**의 브라우저에서 `http://127.0.0.1:8001`을 엽니다. 서버 터미널은 켜 둡니다. 종료하려면 터미널에서 `Ctrl+C`를 누릅니다. 다시 실행할 때는 프로젝트 폴더에서 마지막 실행 명령만 실행하면 됩니다.

8001 포트를 다른 프로그램이 사용한다면 다음처럼 별도 포트를 선택합니다. 이때 접속 주소도 `http://127.0.0.1:8002`로 바꿉니다.

```text
python -m app.demo --port 8002
```

위 `python`은 Windows에서는 `.\.venv\Scripts\python.exe`, macOS·Linux에서는 `.venv/bin/python`으로 실행합니다.

## 준비되는 가상 문의

최초 검수 데이터에는 다음 문의를 한 건 등록합니다.

> 몰타 어학연수를 1월에 3주 정도 가려고 합니다. 참가 가능한가요? 비용도 궁금합니다.

고객 상태는 아직 선택하지 않은 상태로 둡니다. 고객 연락처는 가상 이메일이며 검수용 연락 허용 근거를 기록합니다. `[핵심 조건]`에는 이 문의의 일정·기간·참가 가능 여부와 비용 확인이라는 조건만 준비합니다. 참가 가능 여부나 가격을 확인된 사실로 만들지 않습니다. 1월의 연도도 확정된 것으로 간주하지 않습니다.

검수 DB에서만 `S4-01`~`S4-05` 다섯 문구를 승인합니다. 다른 30개 문구와 일반 실행 DB의 승인 상태는 바꾸지 않습니다.

## 첫 답변부터 일정 확인까지

1. 대시보드 또는 고객 상담에서 몰타 문의를 엽니다.
2. 문의 원문을 읽고 직원이 직접 **S4 · 참가 가능성 검증**을 선택해 저장합니다.
3. 초안 생성 버튼을 누릅니다. 화면의 **모의 응답 · 실제 GPT 생성 아님** 표시를 확인합니다.
4. 초안을 수정합니다. 검수용 문장에서도 참가 가능 여부·가격을 임의로 확정하지 않고, 실제 상담 때 확인할 사항을 구분해 봅니다.
5. 답변 내용 확인 후 승인·모의 발송을 실행합니다. 이 발송은 모의 메일함에만 저장됩니다.
6. 고객 상세 또는 후속관리 현황에서 예약 다섯 개와 문구 ID를 확인합니다. 기준은 방금 모의 발송을 완료한 시각입니다.

| 기준 발송일부터 경과 일수 | 선택 문구 |
| --- | --- |
| 1일 | S4-01 |
| 3일 | S4-02 |
| 7일 | S4-03 |
| 14일 | S4-04 |
| 30일 | S4-05 |

## 시간을 앞당겨 무응답 흐름 확인

검수 화면에 현재 모의 시각과 시간 이동 버튼을 표시합니다. 첫 시작 시각은 서울 시간 `2026-11-05 10:00`이며, 컴퓨터 시계는 변경하지 않습니다. 시간 이동 결과는 검수 DB에 보존됩니다.

첫 모의 발송을 한 뒤 `1일 → 3일 → 7일 → 14일 → 30일` 순서로 시간 이동을 실행합니다. 각 버튼은 직전 후속 발송일부터가 아니라 **직원이 승인한 기준 답변 발송일**로부터 계산합니다. 매번 예약의 적용 문구·원래 예정일·실제 처리 시각·발송 결과를 확인합니다.

기본 영업시간은 서울 시간 평일 09~18시입니다. 해당 경과일이 주말이나 영업시간 밖이면 다음 허용 시간으로 이동해 처리하며 원래 예정 시점보다 앞당기지 않습니다. 원래 예정일과 영업시간을 적용한 실제 처리 시각이 다를 수 있습니다. 이미 지난 시점으로 시간을 되돌리지 않습니다. 검수 환경은 자동 시간 경과 스케줄러 대신 시간 이동 버튼으로 예약 실행을 명시적으로 진행합니다.

## 고객 답장과 새 답변 흐름 확인

무응답 시나리오를 끝낸 뒤에는 **새 검수 문의**로 별도 가상 문의를 만듭니다. 이전 검수 기록은 남겨 두고 새 문의에서 다시 S4 선택·초안 검토·승인 발송을 진행합니다.

1. 기준 답변을 모의 발송하고 `1일`을 실행해 첫 후속 연락을 확인합니다.
2. 고객 답장 테스트 버튼 또는 모의 고객 답장 입력 기능으로 추가 문의를 접수합니다.
3. 남아 있는 예약들이 취소되고 취소 이유가 기록되는지 확인합니다.
4. 고객 상태가 **직원 재선택 대기**가 되는지 확인합니다. 기존 S4를 다시 선택하거나 다른 S0~S6을 선택할 수 있습니다.
5. 상태를 다시 선택한 뒤 새 모의 초안을 생성·수정·승인 발송합니다. 새 답변의 실제 모의 발송 시점을 기준으로 새 주기가 생기는지 확인합니다.

S4 외 상태를 선택하면 해당 문구는 초기 승인 대기이므로 자동 후속 발송이 차단됩니다. 다른 문구를 전체 승인할 필요는 없습니다.

## 현재 발송 문구의 기준과 수정 방법

현재 발송 문구의 기준 저장소는 **SQLite의 `template_versions`**입니다. 원본 Excel은 최초 생성 때 35개 문구를 가져오는 자료이고, 이후 프로그램을 다시 실행한다고 Excel로 덮어쓰지 않습니다.

문구 수정은 사이트의 **후속 문구 → 해당 문구 → 수정·저장**에서 합니다. 수정하면 새 버전이 승인 대기로 생성되므로 관리자가 그 버전을 검토·승인해야 합니다. 기존 예약에 고정된 문구 버전은 새 본문으로 자동 교체하지 않습니다. 승인 취소된 기존 버전을 사용하는 예약은 발송이 보류될 수 있습니다. 문구 변경까지 시험할 때는 새 버전 승인 후 새 상담 답변을 발송해 새 관리 주기를 만들어 확인합니다.

**Google Sheets에서 문구를 수정해도 현재 사이트나 발송 문구에 반영되지 않습니다.** 현재 Sheets 기능은 고객·상담·예약·발송 결과를 SQLite에서 시트로 보고용 내보내기하는 기능입니다. 문구 가져오기나 양방향 동기화는 없습니다. 검수 실행에서는 이 외부 내보내기도 차단합니다.

실제 연동 전 준비 항목은 [연결 설정 안내](CONNECTION_SETTINGS.md)를 참조하세요. 직접 검수가 끝날 때까지 `app.demo`를 사용하고 실제 발송 활성화나 운영 DB 문구 승인으로 전환하지 않습니다.
